# Repository instructions

## Workflow

- Implement one coherent, commit-sized increment at a time, then stop for review.
- Malcolm handles staging, commits, and pushes. Do not run git add, git commit, or git push unless explicitly requested.
- Keep checks appropriate to the change. Do not broaden an increment with unrelated refactors.
- Use Next.js, TypeScript, and the App Router. Export static pages unless an approved feature requires a server.
- Deliver a private preview first. Select a custom domain later, before public launch.
- Do not use a hosting helper that automatically stages, commits, or pushes without explicit authorization.

## Code style

- Follow the applicable conventions in Malcolm's bench/async_client.py style reference.
- Use exactly one blank line between function definitions.
- Do not add docstrings or block comments used as function documentation. Prefer clear names and short line comments only where necessary.
- Keep functions straightforward and use explicit types where useful.
- Follow TypeScript and React naming conventions for components, hooks, and other framework APIs.

## Content

- Do not publish phone numbers or email addresses in site content or the downloadable resume.
- Preserve the original resume and gospel source document.
- Use labeled photo placeholders until Malcolm supplies photographs.
- Do not invent biography, article titles, professional claims, or photographs presented as Malcolm's own.
- Keep the contact form disabled until Formspree is configured; never simulate message delivery.
